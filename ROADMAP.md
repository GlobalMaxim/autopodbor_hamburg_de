## В работе — бэкенд под админку заказчика (`backend/`)

Архитектура сменилась с изначального плана (Payload CMS + Vercel + Cloudflare
R2) на Django + AWS — заказчик сам хостит на AWS, уже есть опыт с Docker.
Подробности решения — `admin-panel-spec.md`, актуальный стек — `architecture.md`.

- [x] Django-проект: `cases` / `reviews` / `process` приложения, модели,
      admin.py (inline-фото/видео, превью, fieldsets), django-ninja API
      (`/api/cases`, `/api/reviews`, `/api/process`)
- [x] Проверено вживую: миграции, суперпользователь, API-роуты, скрытый путь
      админки (`ADMIN_URL` из `.env`, не дефолтный `/admin/`)
- [x] `docker-compose.yml` + `Dockerfile` (frontend и backend) + `Caddyfile`
      (роутинг по пути на одном домене, без CORS)
- [x] Стек реально развёрнут и проверен локально через `docker compose up` —
      логин в админку, CRUD-формы, API — всё через Caddy, не просто "собралось"
- [x] Тема админки — `django-unfold`, акцент в цвет сайта (`#da1626`/`#e92031`,
      та же шкала что в `app/globals.css`), проверено на десктопе и мобильном
      вьюпорте скриншотами — адаптируется само (sidebar → бургер, таблицы
      инлайнов складываются в колонку)
- [ ] Известная непоследовательность (осознанно оставлено как есть): у `Case`
      фото/видео — две отдельные таблицы (`CasePhoto`/`CaseVideo`), `order`
      у каждой свой, не смешиваются. У `Review`/`ReportTopic` — единая
      галерея (`media_type` в одной таблице), `order` общий, чередуются.
      Если понадобится единая галерея и у кейсов — унести на общий паттерн.
- [x] Первая живая связка Next.js ↔ Django: блок "Пример полного осмотра"
      на `/how-it-works` (`#example`) + крупная CTA-кнопка с главной. Темы
      (`ReportTopic`) заводит админ сам через `/admin` — не хардкод, список
      и набор тем полностью динамические. Тема без медиафайлов на сайте не
      показывается. `lib/api.ts` — общий слой для остальных фич (кейсы,
      отзывы подключать по этому же паттерну: ISR revalidate 60с,
      сервер стучится в `django:8000` напрямую, браузер — через Caddy `/api`)
- [ ] Кейсы и отзывы всё ещё на `lib/content.ts` mock — не переключены на API
- [ ] Не задеплоено — нужен AWS Lightsail-сервер, домен → IP, реальный `.env`
      (`DJANGO_SECRET_KEY`, `POSTGRES_PASSWORD`, ключи S3)
- [ ] Миграция текущих mock-кейсов/отзывов в реальную БД
- [ ] Email для приглашения сотрудников (SES/Resend — не выбрано)

## Осознанно не делаем (по финальному ТЗ, п.17)

Конфигуратор, сложные формы заявки, CRM, личные кабинеты,
онлайн-оплата, booking, marketplace, каталог авто,
URL-parser Mobile.de/AutoScout24, AI-анализ объявлений, risk calculator,
WhatsApp как основной CTA.

**Уточнение по "без регистрации/авторизации" (было в п.17):** публичной формы
регистрации для клиентов сайта нет и не будет — с этим противоречий не было.
Учётки сотрудников (для админки) заводит только суперпользователь вручную,
самостоятельной регистрации нет ни для кого — конфликт с ТЗ снят архитектурой,
не нарушением правила.
