# Как добавить видеоотчёт по машине

## 1. Название отчёта (slug)

Придумай короткое имя файла: латиница, цифры, дефисы. Без пробелов, без заглавных букв.

Примеры: `bmw-x5-2021`, `audi-a6-2019`, `mercedes-e220d`.

Файл отчёта: `content/reports/<slug>.json`
Фото: `inbox/<slug>/` → скрипт → `public/reports/<slug>/` (см. раздел 2)

## 2. Фото

Оригиналы с телефона кладёшь в `inbox/<slug>/` (папка не попадает в git):

```
inbox/<slug>/
├── cover.jpg    ← превью в списке «Все видеоотчёты»
├── main/        ← 5 фото: плитки галереи в шапке страницы
└── common/      ← остальные фото: открываются в просмотрщике после клика на «+N»
```

Отдельного блока «Все фото» на странице нет. Просмотрщик листает `main/`, затем `common/`.

Потом один раз `pip install -r scripts/requirements.txt` и для каждой машины:

```bash
python3 scripts/photos.py <slug>
```

Скрипт:
- кладёт готовое в `public/reports/<slug>/`: WebP до 1600 px, превью `NN-thumb.webp` (480 px) и `cover.webp` (900×675);
- удаляет EXIF (геолокацию), нумерует файлы в порядке имён, повторный запуск пересобирает папки целиком;
- пишет `content/photos/<slug>.json` с числом фото, например `{"cover": true, "main": 5, "common": 14}`. Сайт строит адреса по этому файлу, его нужно закоммитить.

Номера и VIN замажь до загрузки в `inbox`. HEIC с iPhone сначала экспортируй в JPG.

### Хранилище фото: Cloudflare R2
1. Загрузи содержимое `public/reports/<slug>/` в бакет по пути `reports/<slug>/` (со вложенными папками).
2. В Vercel добавь переменную `NEXT_PUBLIC_MEDIA_BASE=https://media.твой-домен.de` (адрес бакета без `/` на конце).
3. Закоммить и запушь `content/reports/<slug>.json` и `content/photos/<slug>.json`. Сами фото в git не попадают (`public/reports/` в `.gitignore`).

Фото должны лежать в бакете до пуша. Если `NEXT_PUBLIC_MEDIA_BASE` не задана, сайт берёт фото из `public/reports/` (так работает `npm run dev`).

## 3. JSON отчёта

Создай `content/reports/<slug>.json` по образцу (можно скопировать `example-bmw-x5.json` и поменять значения):

```json
{
  "draft": false,
  "service": "check",
  "inspectedAt": "2026-10-01",
  "title": "Audi A6 55 TFSI",
  "subtitle": { "ru": "2019 · 3.0 бензин · полный привод" },
  "priceEur": 38900,
  "specs": [
    { "label": { "ru": "Марка" }, "value": "Audi" },
    { "label": { "ru": "Модель" }, "value": "A6 55 TFSI" },
    { "label": { "ru": "Год" }, "value": "2019" },
    { "label": { "ru": "Пробег" }, "value": "78 000 км" }
  ],
  "videos": [
    { "provider": "bunny", "id": "abcd1234-...", "title": { "ru": "Диагностика сканером" }, "durationSec": 184 }
  ]
}
```

Подсказки по полям:
- `title` — марка и модель, одна строка, без перевода.
- `subtitle`, `specs[].label`, `specs[].value`, `videos[].title` — можно писать только `{ "ru": "..." }`, сайт сам возьмёт русский текст там, где перевода на другой язык нет. Если хочешь добавить перевод — допиши `"de"` и/или `"uk"` в тот же объект.
- `priceEur` — только число, без "€" и пробелов. Если цены нет — просто убери строку.
- `inspectedAt` — дата осмотра в формате `ГГГГ-ММ-ДД`.

### Где взять `id` видео в Bunny Stream

1. Зайди в панель Bunny Stream → нужная библиотека → видео.
2. Открой нужное видео, во вкладке "Overview" или в адресной строке найди **Video ID** (длинная строка вида `a1b2c3d4-...`).
3. Вставь это значение в поле `"id"` соответствующего видео в JSON.

Пока `"id"` пустой — видео на сайте показывается как заглушка (не кликается). Это ручной способ — для машины с коллекцией в Bunny (раздел ниже) он не нужен, видео подхватываются сами.

## 4. Видео из Bunny (основной способ)

Обычно видео не прописывают в JSON руками — они лежат в Bunny Stream, а сайт подтягивает их список из `data/videos.generated.json`.

**Порядок:**

1. В Bunny Stream создай коллекцию с именем = `slug` отчёта (`bmw-x7`).
2. Загрузи туда видео, каждому дай имя `<тема>-<номер>`: `lkp-1`, `lkp-2`, `interior-1`, `scanner-3`. `<тема>` — это `id` из `content/topics.json` (lkp, scanner, interior, engine, drive, mileage). Видео без цифры в конце (`intro`) считается первым в своей группе.
3. Запусти из корня проекта:
   ```bash
   node --env-file=.env.local scripts/sync-bunny.mjs
   ```
   Нужен `BUNNY_API_KEY` в `.env.local` (ключ библиотеки Stream, не общий ключ аккаунта).
4. Закоммить и запушь обновлённый `data/videos.generated.json`.

Сайт сам: группирует видео по `<тема>` в блоки на странице машины (заголовок блока — `groupTitle` темы), ставит заголовок карточки «Видео 1», «Видео 2»… по номеру, берёт длительность и превью из Bunny.

**Своё название вместо «Видео N»**

Добавь в `content/reports/<slug>.json` поле `"titles"` — ключ — точное имя видео в Bunny, значение — заголовок:

```json
{
  "titles": {
    "lkp-1": { "ru": "Капот и крыша" }
  }
}
```

Остальные видео (без записи в `titles`) останутся «Видео N» / «Video N» / «Відео N» по языку.

**Видео без известной темы в имени** (опечатка или произвольное название без номера) остаются на странице машины отдельным блоком без заголовка — в папки «Как мы проверяем» (раздел 6) они не попадают, сборка на это не падает.

**Если у машины нет коллекции в Bunny** — всё работает как раньше: видео только из массива `"videos"` в JSON отчёта, вручную с `id` и `topic` (разделы 3 и 6).

## 5. Публикация

Пока `"draft": true` — отчёт виден только тебе на локальном сервере (`npm run dev`), на сайте в продакшене его не видно (ни страницы, ни карточки в списке, ни в поиске).

Когда отчёт готов — поставь `"draft": false`, и он появится на сайте после следующей сборки/деплоя.

## 6. Как видео попадает в папку «Как мы проверяем»

На странице списка `/video-reports` есть блок с папками по темам (Проверка ЛКП, Работа со сканером и т. д.) — он собирается из `content/topics.json`. Материалы в папке берутся из трёх источников:

**1. Видео из коллекции Bunny — автоматически.** Если имя видео в Bunny начинается с `<тема>-` (раздел 4) — оно само попадает в папку этой темы, ничего отдельно указывать не нужно.

**2. Видео из отчётов по машинам, добавленные вручную (через поле `topic`)**

Добавь в видео отчёта поле `"topic"` со значением `id` нужной темы из `content/topics.json`:

```json
{ "provider": "bunny", "id": "abcd1234-...", "title": { "ru": "Замер ЛКП толщиномером" }, "durationSec": 184, "topic": "lkp" }
```

Видео без `topic` просто не попадает в папку, но остаётся видно на странице своей машины — как обычно.

Значение `topic` должно совпадать с одним из `id` в `content/topics.json`, иначе `npm run build` упадёт с ошибкой и укажет, в каком файле опечатка. Для видео из коллекции Bunny неизвестный префикс в имени (не совпадает ни с одной темой) ошибкой не считается — видео просто не попадает ни в одну папку.

**3. Фото из отчётов в папки тем не попадают.** Фото в отчёте не делятся на категории, поэтому в папку темы добавляются только видео (пункты 1–2) и собственные материалы темы (пункт 4).

**4. Собственные материалы темы — без привязки к машине**

Если у темы нет подходящего видео или фото из отчётов (или просто хочется показать что-то общее, не привязанное к конкретному авто) — добавь материалы прямо в `content/topics.json`:

- видео — массив `"videos"` у темы, в том же формате, что у отчётов (`provider`, `id`, `title`, `durationSec`, необязательный `poster`), только без `topic`;
- фото — положи файлы в `public/topics/<id>/` (имена файлов как в `public/reports` — `01.webp`, `02.webp`…), создавать запись в JSON для этого не нужно.

**Как добавить новую тему**

Допиши ещё одну запись в массив `content/topics.json`:

```json
{
  "id": "brakes",
  "title": { "ru": "Тормозная система" },
  "description": { "ru": "Диски, колодки, суппорты — замеры и визуальный осмотр." }
}
```

Порядок записей в файле = порядок папок на странице. Если у темы нет ни одного материала (ни своего, ни из отчётов) — на продакшене она просто не показывается; на локальном сервере (`npm run dev`) видна с плейсхолдерами, чтобы было видно, что тема существует, но пустая.

## 7. Как проверить, что всё правильно

Запусти в терминале:

```
npm run build
```

Если в JSON ошибка (опечатка, пропущенное поле, неверный формат даты) или в папке с фото лишняя/неправильно названная подпапка — сборка остановится и покажет, в каком файле и что не так. Поправь и запусти `npm run build` снова.
